WebSocketRadioTransport

class WebSocketRadioTransport : RadioTransport(source)

The phone API over a WebSocket at url, as firmware serves it at /api/v1/ws: one binary message per ToRadio or FromRadio, no stream header, one client at a time.

Reconnects by itself with ReconnectBackoff, as TcpTransport does, until close or a close code that says retrying cannot help: 4001 (another client took the slot) and 1009 (a message over firmware's limit). 1013 (the radio is out of heap) waits at least WebSocketTiming.tryAgainLaterDelay. A link with nothing inbound for WebSocketTiming.inactivityTimeout is dropped and redialled; firmware answers every keepAlive with a QueueStatus, so silence means a half-open socket.

ESP32 firmware aborts a displaced client without a close frame when it cannot write, so a 4001 may never arrive. After MAX_QUICK_DROPS sessions in a row that open and then drop without a close frame inside ReconnectBackoff.SHORT_SESSION_THRESHOLD_MS, the transport stops with TransportDisconnectReason.WebSocketSlotContested rather than keep taking the slot back from the other client.
