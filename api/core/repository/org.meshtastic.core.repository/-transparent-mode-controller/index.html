TransparentModeController

class TransparentModeController(radioConfigRepository: RadioConfigRepository, serviceRepository: ServiceRepository, radioController: RadioController, nodeManager: NodeManager, scope: CoroutineScope)(source)

Tracks whether the connected node is in transparent mode (a raw LoRa modem for a host such as meshtasticd), what the user chose to do about it for this connection, and turns it off on request.

It never writes the local config cache. The cache follows the node's own answers, which the admin handler stores bound to the session they arrived on, so a turn-off that outlives its connection cannot put one node's config in another's cache.

suspend fun confirmTurnedOnByUser(savedOn: LocalNodeConnection): Boolean?

Reads transparent_mode back after the user saved it on from settings over savedOn, and returns what the node reports, or null when it did not answer on that connection or the connection has changed since. The notice stays back while the read is out, and afterwards unless the node reports the mode off: firmware that does not know the field accepts the write and drops it, so that is not the user's choice taking effect.

turnOff

fun turnOff(savedOn: LocalNodeConnection? = null)

Reads the node's LoRa config, sends it back with only transparent_mode cleared, and reads it again. The outcome is TransparentModeTurnOff.TURNED_OFF only when that second read says so. The attempt runs in the controller's own scope and ends without an outcome when its connection does. With savedOn it starts only while that is still the connection, so a settings save cannot hand its turn-off to another one.
